Architecture Review  ·  Scalability

Is it highly scalable at thousands of RPS?

Scalable by design — not yet by provisioning. The rework-risk seams are correctly locked in Phase 1, so what's left is additive. But for the agentic paths, “RPS” is the wrong unit: the ceiling is provider quota, cost, and model latency — think tens of thousands of concurrent streams, not thousands of new LLM requests per second. The two blind spots this review surfaced are now written into the specs; what remains is Phase-4 provisioning.

02 Two blind spots this review surfaced — now closed

The per-query LLM multiplier Documented

One user query is not one LLM call. The graph runs route → rewrite → retrieve → rerank → generate — a routing call, a rewrite call, a Cohere rerank call, and a generation call.

1000 query/s ≈ 4000–5000 provider calls/s
× key-pool quota × $ per call = the real ceiling

Every provider-quota and cost estimate must carry this ~5× factor. Credits meter the burn; they add no capacity.

Now in: agent-graph.md (per-query call-count note) · research §21 (provider-capacity math) · draft-plan #9 (load/SLO plan).

Redis-Cluster pub/sub collision Documented

The stateless SSE relay is a genuinely strong seam — but it rides Redis pub/sub keyed by stream_id. Move Redis to Cluster for HA (Phase 4 P1) and classic pub/sub broadcasts every message across the whole cluster bus.

The fix — sharded pub/sub (SPUBLISH/SSUBSCRIBE, Redis 7+) on a slot-hash-tagged stream_id — is now written down, and the SSE-tier split and Redis-HA move are marked as one coupled workstream, not two phases.

Now in: sse-events.md (scaling caveat) · research §10(d) · draft-plan #2 + #6 (cross-linked).

03 What I escalated — now resolved in-spec

✓ 01

SSE × Redis-Cluster pub/sub fan-out. The single biggest concurrency risk (P0) and its HA plan (P1) interact through an unspecified sharded-pub/sub decision. They are now cross-linked as a single workstream to resolve together.

Resolved in: draft-plan Phase 4 #2 ↔ #6 · sse-events.md · research §10(d).

✓ 02

The 4–5× LLM-call multiplier is now required in every quota/cost/SLO calc, and the load-test harness (P2) now carries a $/QPS budget and a concurrent-streams primary target — not just an RPS number.

Resolved in: draft-plan Phase 4 #9 · research §21 · agent-graph.md.

Bottom line — the irreversible decisions (async decoupling, stateless relay, idempotent-with-DB-backstop, partitionable money path, data-layer isolation) are correct and locked, so Phase 4 is genuinely provisioning + HA + load validation, not redesign. The two blind spots above — the SSE/Redis-Cluster pub/sub coupling and the per-query LLM-call multiplier — are now specified in the Phase 1 docs (design-closed; implementation stays Phase 4), plus an interim per-tenant in-flight cap that need not wait for Phase 4. As provisioned today it would not survive thousands of RPS; every mechanism to get there is now enumerated and cross-referenced.
